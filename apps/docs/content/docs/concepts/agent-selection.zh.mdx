---
title: Agent 选择
description: Tessera Agent 如何为单次模型调用提供最小但足够的 Component Contract Slice。
---

模型不会通过 React Component Name 或视觉外观选择 UI。Host 会冻结当前任务专属的
`CatalogSetSlice`，Compiler 再从这份 Slice 生成唯一允许使用的 `present_ui` Tool Schema 与 Prompt。

## 选择流程

1. Tessera Agent 通过语义规划与服务端拥有的受限查询回答分析问题。
2. Host 发布绑定 Grant 的 Resource 与 Evidence Offer；Query Row 继续留在 Resource Gateway 后面。
3. Host 创建冻结 Catalog Slice，只包含有用的 Component 与 Action Contract、依赖、精确 Revision 与 Limit。
4. `compilePresentUi()` 从经过校验的 Slice 生成 Provider Schema 与模型指导。
5. 模型只能调用 `present_ui`，并且只能引用已提供的 Component、Resource、Evidence、State 与 Action Identity。
6. `ProposalCompilerTurn` 在固定 Budget 内执行 Decode、Normalize、Validate、Repair，并通过共享 Server Boundary Commit。
7. 可信 `SurfaceEventStream` 把生成的 Revision 发布到浏览器。

## 当前选择词汇

Tessera Agent 成功证明的完整 Catalog 只提供 `data.chart`。具体选择发生在严格 Recipe Union 内：

| 分析需求 | Recipe 示例 |
| --- | --- |
| 有序进度 | Steps Bars、Pipeline Stage Bars、Sign-up Funnel |
| 趋势与比较 | Revenue Smooth Area、Visitors Stacked Area、Sessions + Conversion Combo |
| 分布与关系 | Revenue per Account Scatter、Tracked Time Sankey |
| 周期与强度 | Activity Calendar、Active Users Heatmap、Contributions Heatmap |
| 紧凑状态 | Sleep Score、Visitors Radial、Visitors Radar、Devices Bars、Activity Rings |

这些名称是 `spec.recipe` 值，不是 Component Contract Name。Host 可以在单次 Turn 中进一步收窄
允许的 Recipe Enum 与 Column Binding，而不创建第二份 Schema 或第二条 Renderer 路径。

## 选择不变量

模型不能扩大 Slice、虚构 Binding、选择任意 Renderer，也不能通过 URL 请求原始数据。正向与负向
Contract 指导、稳定字段、严格 Schema 与 Data Agent Golden Example 会提高首轮选择准确率，
同时无需把完整 Catalog 或 Query Result 放进每一个 Prompt。

渲染与交互始终发生在选择之后。Committed Node 一律通过 `SurfaceController`、
`GenerativeSurface` 与精确 `RendererRegistry` 渲染；选择过程不会直接调用组件。
