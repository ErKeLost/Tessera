Data Elements 将模型编写的声明与宿主掌控的执行、渲染、身份和持久化分开。模型既不生成可执行 UI
代码，也不能直接生成可信 Runtime Object。

本文概述当前已经落地的 v2 基础。规范性的产品与生命周期设计见
[嵌入式业务 Artifact Runtime](./embedded-artifact-runtime)：它是嵌入现有业务系统、可持久化并持续编辑的
Artifact，而不是 App 生成器。

```text
用户请求 + 宿主授权的数据
  -> 每轮 Catalog Slice 与 Surface DSL Schema
  -> 模型 Proposal
  -> 服务端 Compiler：Decode、Normalize、Validate、Authorize、Commit
  -> 带本地 Brand 的 v2 ArtifactPart
  -> 序列化 ArtifactPartWire
  -> 客户端 decodeArtifactPart(..., { contractFingerprint })
  -> React ArtifactRenderer 与 shadcn/ui Recipe
  -> 宿主授权的 Runtime Command
```

本地 Brand 只会在校验后施加，而且不会跨网络序列化。因此，每个 `ArtifactPartWire`
都必须先使用预期的 Contract Fingerprint 重新 Decode，才能交给 `ArtifactRenderer`。

## Package 边界

| 边界 | Package | 职责 |
| --- | --- | --- |
| v1 兼容契约 | `@data-elements/schema` | 18 种语义 Artifact Schema 与类型化 v1 Action Event |
| 语义目录 | `@data-elements/core` | 语义 Manifest、选择规则、Contract Graph 与可信 Calculator |
| v2 Runtime | `@data-elements/runtime` | Normalized IR、Wire Decode 与 Brand、校验、事务、Replay、Migration 和本地 Action |
| Authoring 与 Commit | `@data-elements/compiler` | 仅服务端使用的 Surface DSL、每轮 Catalog Slicing、Prompt 编译、有限修复、Policy Check 与 Runtime Commit |
| 权限边界 | `@data-elements/capability-broker`, `@data-elements/resources` | 仅服务端使用的 Grant、Approval、Effect、Scoped Resource、Evidence 与 Receipt |
| 渲染 | `@data-elements/react` | React Renderer、Provider Runtime、State/Resource Binding、官方 Node 与 v1 兼容入口 |
| 框架 Adapter | `@data-elements/ai-sdk`, `@data-elements/mastra`, `@data-elements/ag-ui` | 连接共享 Compiler 与 Commit 边界的轻量服务端映射 |
| 分发 | shadcn Registry + npm | 可编辑 React 源码，以及精确版本的 Schema、Core 与 Runtime 依赖 |

浏览器代码可以依赖 Schema、Core 和 Runtime，但不能包含 Compiler、Prompt Example、
Capability Broker、Resource Resolver、Credential 或服务端 Policy 实现。

## 一个 Catalog，两层 Node

标准 Compiler Catalog 当前包含 30 个带版本的 Node Contract：

- **18 个语义 Artifact：** Query、Calculator、Metric、Comparison、Trend、Anomaly、
  Forecast、Funnel、Data Quality、Insight、Breakdown、Distribution、Cohort、Experiment、Driver、
  Ranking、Target 与 Timeline。
- **7 个 Surface Node：** Stack、Grid、Section、Text、Callout、Progress 与 Empty。
- **5 个 Form Node：** Form Root、Input、Select、Toggle 与 Button。

`prepareTurn()` 只选择当前任务真正需要的子集，并从这些 Contract 生成 Provider Schema 与
Prompt。扩展能力通过 Compiler Catalog 和对应的 React Node Renderer 接入，不需要另造 Wire Protocol。

## Commit 后再渲染

严格语义 Node 只有在校验并 Commit 后才会挂载。渐进式 Surface Shell 可以在新 Proposal
仍处于校验阶段时保留 last-good Revision，但原始模型文本、未完成 Tool Input 与没有 Brand
的 Wire Data 永远不能进入 Renderer。

同一份已提交 Document 可以内联、显示在 Workbench 或占据完整页面，无需改变协议。UI Event
会变成类型化 Runtime Command，而且只能通过宿主授权的 `runtimeTransport` 执行；Renderer
绝不能直接调用任意 Data Tool。

[嵌入式业务 Artifact Runtime](./embedded-artifact-runtime)。DSL、IR、Compiler 和 v2 实现细节继续保留在
[协议与 Compiler 参考](./artifact-ui-architecture)。
