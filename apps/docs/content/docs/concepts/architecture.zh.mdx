Tessera Agent 把模型编写的声明与宿主掌控的数据、身份、校验、权限、状态、Effect、持久化、
Commit 与渲染彻底分开。模型既不生成可执行 UI 代码，也不能直接生成可信 Runtime Object。

## 唯一 Canonical Path

```text
用户问题 + 宿主授权的 Resource Offer
-> 冻结 CatalogSetSlice
-> 模型提议声明式 Node
-> Compiler Normalize、Validate、Authorize 与 Commit
-> HostServer 发布可信 SurfaceEventStream
-> SurfaceController Replay 事件并解析 Node Projection
-> GenerativeSurface 遍历 Canonical Graph
-> RendererRegistry 精确解析 Component Contract Renderer
-> @open-generative/ui 渲染 Tessera Agent 的 shadcn/Recharts 组件
```

这套架构没有 `ArtifactPart`、浏览器 Decoder、`ArtifactRenderer`、旧兼容 Facade 或第二条按
Artifact 分叉的渲染路径。原始模型输出永远不会进入 React。

## Package Boundary

| 边界 | Package | 职责 |
| --- | --- | --- |
| Canonical Value 与 Wire Protocol | `@open-generative/protocol` | Document、Operation、Stream、ID、Hash、Limit 与 Diagnostic |
| Contract Identity 与 Manifest | `@open-generative/catalog` | Immutable Component Contract、Catalog Slice、Placement 与 Renderer Capability Negotiation |
| Proposal 验收 | `@open-generative/compiler` | 仅服务端 Decode、Normalize、Validate、Repair、Policy 与 Commit Gate |
| 确定性状态 | `@open-generative/runtime` | Document、Preview、State、Replay、Revision DAG 与 Migration Reducer |
| Host 编排 | `@open-generative/server` | Session、Transaction、Event Journal、Authority 与可信发布 |
| 浏览器控制 | `@open-generative/client` | 可信事件 Replay、Resolved Node Projection、Resume 与 Host Command |
| Resource Data | `@open-generative/resources` | 仅服务端 Schema、Grant、Projection、Window 与 Evidence |
| Effect | `@open-generative/capabilities` | 仅服务端 Action Policy、Approval、Idempotency、Effect 与 Receipt |
| React Binding | `@open-generative/react` | `GenerativeSurface`、精确 `RendererRegistry`、Placement 与 System Surface |
| Data Agent Contract | `@open-generative/components` | 12 个 Contract、Props Schema、Chart Spec、Recipe 与 Fixture |
| Data Agent UI | `@open-generative/ui` | 官方 shadcn/Recharts Node Renderer 与 Registry Factory |

Framework Adapter 可以转换 Transport 细节，但不能拥有或替换这些语义。Browser Code 不能引入
Compiler、Server、Resource、Capability、Credential、Prompt Example 或签名材料。

## 当前 Component Contract Slice

成功证明使用 12 个正交 Contract：

- Layout：`layout.stack`、`layout.grid`、`layout.section`
- Content：`content.text`、`content.callout`、`content.empty`
- Data：`data.metric`、`data.table`、`data.chart`、`data.query-details`
- Control：`control.filter`、`control.group`

Trend、Comparison、Funnel、Cohort、Anomaly、Forecast 与 Data Quality 都是 Composition Recipe，
不是额外协议类型。这样既保持模型可见 Slice 足够小，也能构建产品级分析界面。

## Commit 与 Preview

Layout 与安全 Content 可以通过经过校验的只读 Preview 渐进出现；Resource-backed Data 与
State-bound Control 必须原子 Commit。Preview Renderer 不会得到 Event Emitter，因此未完成内容
不能触发 Host Command。Proposal 失败时继续保留 Last-good Committed Revision。

Resource Payload 不进入 Canonical Document。`SurfaceController` 只在渲染前，根据可信且绑定 Grant
的 Projection，为单个 Node Materialize 并校验 Resolved Props。
