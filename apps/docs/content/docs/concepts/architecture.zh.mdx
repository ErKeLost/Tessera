title: 产品架构
description: 让 Tessera Agent 数据库回答受治理、可持久化且可检查的运行时边界。
---

Tessera Agent 把模型决策与数据库 Authority 分开。模型可以选择已注册 Tool 并提出受限 Input；
Catalog、权限、执行、Evidence、持久化与最终浏览器 Projection 都由 Tessera 掌控。

## Runtime Flow

```text
浏览器问题
-> Nitro Chat Route
-> Mastra Agent
-> 受治理数据库 Tool
-> Connector Execution
-> Evidence 与 Resource Publication
-> 文字或生成式分析视图
-> AI SDK UI Message Stream
-> Studio Transcript 与 Renderer
```

Data Agent 只有两条明确查询路径。物理 Metadata 与 SQL 工作使用
`list_database -> execute_sql`；语义分析使用
`search_data_context -> prepare_analysis -> execute_sql(analysisRef)`。两条路径最终进入同一个业务
数据执行 Tool，系统不会为了产生更多输出而随意混合它们。

## 所有权

| 层 | 职责 |
| --- | --- |
| Studio Client | 对话、Tool 生命周期、分析视图、Approval、Settings 与刷新恢复 |
| Nitro Server | Authentication Boundary、Chat Transport、Transcript Projection、Settings 与 Runtime Lease |
| Mastra Agent | Model Loop、Processor、Tool、逐 Step Memory 与 Durable Suspend/Resume |
| Data Agent | Semantic Catalog Scope、Plan Validation、服务端 Compilation、Bounded Execution 与 Evidence |
| Database Connector | Catalog Inspection、Dialect Behavior、Bounded Query 与 Typed Effect |
| Local Store | Thread Memory、UI Transcript Metadata、Workflow Checkpoint 与 Action Receipt |

## 两份历史记录

Mastra Memory 在每个已完成 Step 后保存模型私有上下文。Studio 在每个 AI SDK `onStepEnd` 后
保存另一份 Browser-safe Transcript。两者有意不同：模型历史保留 Continuation 所需 Tool Context，
浏览器历史只包含 Allowlist Display Data。

## 生成式视图

生成式分析视图是 Tessera Agent 的一种回答格式。它只消费已经由成功数据库 Tool 发布的 Resource，
不能再次执行查询。Client 使用 Studio 内置组件渲染唯一最新、已经 Commit 的 Data Part。
