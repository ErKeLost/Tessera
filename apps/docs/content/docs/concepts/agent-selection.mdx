---
title: Analysis Selection
description: How Tessera chooses database tools for a grounded final response.
---

Tessera makes one authoritative decision during a data question: how to obtain
verified data. Answer composition never gains database authority and never
changes the selected query path.

## Database path selection

The Agent instructions and typed tool schemas steer the model toward one of two
paths:

| Analytical intent | Primary path |
| --- | --- |
| Physical schema, explicit SQL, exact rows | `list_database -> execute_sql` |
| Semantic metrics, dimensions, rankings, trends | `search_data_context -> prepare_analysis -> execute_sql(analysisRef)` |

Tool output contains bounded evidence and stable column metadata. Invalid tool
arguments return a structured rejection; they are not interpreted as proof
that data is missing.

## Answer composition

The final model step receives only the validated tool results and Evidence
needed to explain the answer. Its output is parsed and validated before it is
stored or streamed to the browser. It cannot contain credentials, raw SQL,
arbitrary tool definitions, or executable content.
