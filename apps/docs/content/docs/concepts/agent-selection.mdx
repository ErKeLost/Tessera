---
title: Agent Selection
description: How Tessera Agent offers the smallest useful Component Contract slice to one model turn.
---

The model does not choose UI by React component name or visual appearance. The
Host freezes a task-scoped `CatalogSetSlice`, and the compiler derives the only
allowed `present_ui` tool schema and prompt from that slice.

## Selection flow

1. Tessera Agent answers the analytical question through semantic planning and
   a bounded server-owned query.
2. The Host publishes grant-bound Resource and Evidence offers. Query rows stay
   behind the Resource Gateway.
3. The Host creates a frozen Catalog slice containing only useful Component and
   Action Contracts, their dependencies, exact revisions, and limits.
4. `compilePresentUi()` derives the provider schema and model guidance from the
   verified slice.
5. The model calls only `present_ui` and may reference only offered component,
   resource, evidence, state, and action identities.
6. `ProposalCompilerTurn` decodes, normalizes, validates, repairs within the
   fixed budget, and commits through the shared server boundary.
7. A trusted `SurfaceEventStream` publishes the resulting revision to the
   browser.

## Current selection vocabulary

The complete Tessera Agent proof catalog contains 12 contracts, but a turn may
receive fewer:

| Need | Offered contracts |
| --- | --- |
| Narrative answer | `layout.stack`, `layout.section`, `content.text`, `content.callout` |
| KPI summary | `layout.grid`, `data.metric` |
| Trend or comparison | `data.chart` with a valid ChartSpec recipe |
| Row inspection | `data.table` and, when useful, `data.query-details` |
| Refinement | `control.group`, `control.filter`, and a Host-offered action binding |
| No usable result | `content.empty` |

Trend, funnel, cohort, anomaly, forecast, ranking, and data-quality are not
selectable protocol component names. They are evaluated composition recipes
over this vocabulary.

## Selection invariants

The model cannot expand the slice, invent a binding, choose an arbitrary
renderer, or request raw data by URL. Positive and negative Contract guidance,
stable fields, strict schemas, and data-agent golden examples improve first-pass
selection without putting the full catalog or query results in every prompt.

Rendering and interaction remain downstream of selection. A committed node is
always rendered through `SurfaceController`, `GenerativeSurface`, and the exact
`RendererRegistry`; selection never creates a direct component invocation.
