---
title: Product architecture
description: The runtime boundaries that make Tessera Agent's database answers governed, durable, and inspectable.
---

Tessera Agent separates model decisions from database authority. The model can
choose a registered tool and propose bounded input; Tessera owns the catalog,
permissions, execution, evidence, persistence, and final browser projection.

## Runtime flow

```text
browser question
-> Nitro chat route
-> Mastra Agent
-> governed database tool
-> connector execution
-> evidence and resource publication
-> text or generated analysis view
-> AI SDK UI Message Stream
-> Studio transcript and renderer
```

The Data Agent uses two explicit query paths. Physical metadata and SQL work use
`list_database -> execute_sql`; semantic analysis uses
`search_data_context -> prepare_analysis -> execute_sql(analysisRef)`. Both end
at the same business-data execution tool. A request does not mix those paths
merely to produce more output.

## Ownership

| Layer | Responsibility |
| --- | --- |
| Studio client | Conversation, tool lifecycle, analysis views, approvals, settings, and refresh restoration |
| Nitro server | Authentication boundary, chat transport, transcript projection, settings, and runtime leases |
| Mastra Agent | Model loop, processors, tools, per-step Memory, and durable suspend/resume |
| Data Agent | Semantic catalog scope, plan validation, server-only compilation, bounded execution, and evidence |
| Database connectors | Catalog inspection, dialect behavior, bounded queries, and typed effects |
| Local stores | Thread Memory, UI transcript metadata, workflow checkpoints, and action receipts |

## Two histories

Mastra Memory stores private model context after every completed step. Studio
stores a separate browser-safe transcript after every AI SDK `onStepEnd`. The
two records are deliberately different: the model history can retain tool
context needed for continuation, while the browser transcript contains only
allowlisted display data.

## Generated views

Generated analysis views are one Tessera Agent response format. They consume
only resources already published by successful database tools and cannot
perform another query. The client renders one latest, committed data part with
Studio's built-in components.

Read the [tool contract](/docs/agent/tool-contract), [run loop](/docs/agent/architecture/run-loop),
and [generated analysis view](/docs/agent/architecture/generative-ui) pages for
