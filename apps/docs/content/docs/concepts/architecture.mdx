Tessera Agent separates model-authored declarations from host-owned execution,
rendering, identity, and persistence. The model never produces executable UI
code or a trusted runtime object.

This page summarizes the implemented v2 foundation. The normative product and
lifecycle design is the
[Embedded Business Artifact Runtime](./embedded-artifact-runtime): a persistent,
continuously editable Artifact embedded in an existing business system, not an
application generator.

```text
User request + host-authorized data
  -> per-turn catalog slice and Surface DSL schema
  -> model proposal
  -> server compiler: decode, normalize, validate, authorize, commit
  -> locally branded v2 ArtifactPart
  -> serialized ArtifactPartWire
  -> client decodeArtifactPart(..., { contractFingerprint })
  -> React ArtifactRenderer and shadcn/ui recipes
  -> host-authorized runtime commands
```

The local brand is applied only after validation. It is not serialized across a
network boundary, so every `ArtifactPartWire` must be decoded again with the
expected contract fingerprint before it reaches `ArtifactRenderer`.

## Package boundaries

| Boundary | Package | Responsibility |
| --- | --- | --- |
| v1 compatibility contracts | `@open-generative/protocol` | The 18 semantic artifact schemas and typed v1 action events |
| Semantic catalog | `@open-generative/catalog` | Semantic manifests, selection guidance, contract graph, and trusted calculators |
| v2 runtime | `@open-generative/runtime` | Normalized IR, wire decoding and branding, validation, transactions, replay, migration, and local actions |
| Authoring and commit | `@open-generative/compiler` | Server-only Surface DSL, per-turn catalog slicing, prompt compilation, bounded repair, policy checks, and runtime commit |
| Authority boundaries | `@open-generative/capabilities`, `@open-generative/resources` | Server-only grants, approvals, effects, scoped resources, evidence, and receipts |
| Rendering | `@open-generative/react` | React renderer, provider runtime, state/resource bindings, official nodes, and v1 compatibility |
| Framework adapters | `@open-generative/ai-sdk`, `@open-generative/mastra`, `@open-generative/ag-ui` | Thin server-side mappings onto the shared compiler and commit boundary |
| Distribution | shadcn registry + npm | Editable React source with exact-version schema, core, and runtime dependencies |

Browser code may depend on schema, core, and runtime. It must not include the
compiler, prompt examples, capability broker, resource resolver, credentials,
or server policy implementation.

## One catalog, two node layers

The standard compiler catalog currently contains 30 versioned node contracts:

- **18 semantic artifacts:** query, calculator, metric, comparison, trend,
  anomaly, forecast, funnel, data quality, insight, breakdown, distribution,
  cohort, experiment, driver, ranking, target, and timeline.
- **7 Surface nodes:** stack, grid, section, text, callout, progress, and empty.
- **5 form nodes:** form root, input, select, toggle, and button.

`prepareTurn()` selects only the useful subset for one task and derives the
provider schema and prompt from those contracts. Extensions enter through the
compiler catalog and a matching React node renderer; they do not require a new
wire protocol.

## Commit before render

Strict semantic nodes mount only after validation and commit. Progressive
Surface shells may preserve a last-good revision while a new proposal is still
being validated, but raw model text, partial tool input, and unbranded wire data
never reach the renderer.

The same committed document can render inline, in a workbench, or on a full page
without changing its protocol. UI events become typed runtime commands and are
executed only through a host-authorized `runtimeTransport`; a renderer never
calls an arbitrary data tool directly.

[Embedded Business Artifact Runtime](./embedded-artifact-runtime). The detailed
