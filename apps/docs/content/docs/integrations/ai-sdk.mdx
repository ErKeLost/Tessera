---
title: AI SDK transport
description: How Tessera Agent uses AI SDK v7's native UI message stream and step callbacks.
---

Tessera Studio uses the AI SDK v7 UI Message Stream protocol between its Nitro
server and React client.

## Native stream assembly

Mastra's stream is converted through `@mastra/ai-sdk`, then passed to AI SDK's
official `createUIMessageStream`. AI SDK owns text, reasoning, tool, data-part,
`reset-step`, and repeated part-ID assembly.

```ts
const stream = createUIMessageStream<TesseraUIMessage>({
  execute: ({ writer }) => writer.merge(agentStream),
  onStepEnd: async ({ responseMessage }) => {
    await checkpointUiMessage(responseMessage);
  },
  onEnd: async ({ responseMessage, isAborted, finishReason }) => {
    if (!isAborted && finishReason === "stop") {
      await checkpointUiMessage(responseMessage);
    }
  },
});

return createUIMessageStreamResponse({ stream });
```

AI SDK documents `onStepEnd` specifically for persisting intermediate UI
messages in multi-step agent runs. Tessera therefore does not maintain a second
chunk assembler or compatibility protocol.

## Tessera data parts

Normal text, reasoning, and tools remain native AI SDK parts. A generated
analysis view is delivered as one typed `data-openGenerativeSurface` part
inside the Tessera message type. The Studio renderer recognizes that data part.

The server stores only an allowlisted projection. Cumulative updates for one
analysis surface replace the earlier snapshot, and every step checkpoint
upserts the same assistant message ID. Refreshing a thread therefore restores
one message and one latest surface rather than replaying duplicate snapshots.
