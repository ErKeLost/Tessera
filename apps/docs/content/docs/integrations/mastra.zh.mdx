`@open-generative/mastra` 是已经实现的 Mastra 1.61 服务端 Adapter。它调用 Mastra 真正的
`createTool()` API，把 Compiler Output 转成 Request-scoped `present_ui` Tool，不创建第二套
Protocol、Compiler、Runtime 或 Renderer。

## 创建本轮 Adapter

`createMastraIncrementalPresentUi()` 返回本轮必须绑定在一起的值：Compiler System Prompt、
准确的 Compiled Contract、`tools.present_ui`，以及强制使用的 Tracing Options。Mastra 1.61
的三个原生 Input Hook 会把完整 Operation Frame 送入同一个 Incremental Compiler Session，
最终仍由 `execute` 完成确认。

```ts
import {
  compilePresentUi,
  createIncrementalPresentUiCompilerSession,
} from "@open-generative/compiler";
import { createMastraIncrementalPresentUi } from "@open-generative/mastra";
import { Agent } from "@mastra/core/agent";

const compiled = compilePresentUi({ catalog: turnCatalog });
const presentUi = createMastraIncrementalPresentUi({
  compiled,
  maxAttempts: 3,
  createSession: ({ toolCallId, abortSignal }) =>
    createIncrementalPresentUiCompilerSession({
      compiled,
      turn: createTurnForRequest({ toolCallId, abortSignal }),
    }),
});

const agent = new Agent({
  id: "tessera-data-agent",
  name: "Tessera Data Agent",
  model,
  instructions: presentUi.system,
  tools: { ...domainTools, ...presentUi.tools },
});

// 每个请求只选择一种执行模式；两种模式都必须携带 Tracing Gate。
const result = await agent.generate(messages, {
  tracingOptions: presentUi.tracingOptions,
});
const stream = await agent.stream(messages, {
  tracingOptions: presentUi.tracingOptions,
});
```

上面的 `createTurnForRequest()` 是 Tessera Host Composition Helper，负责使用本请求冻结的
Catalog Slice、Authority、Transaction 和 Runtime 创建正式的 `ProposalCompilerTurn`。应用只需要
Tool Instance 时可以直接调用 `createMastraIncrementalPresentUiTool()`；只创建 Tool 的 Host 必须自行
导入并传入 `MASTRA_PRESENT_UI_TRACING_OPTIONS`。Adapter 会在最终确认前使用 Compiler Canonical
Schema 验证完整输入。无效输入会抛出 `MastraPresentUiInputError`，稳定错误码是
`mastra.present-ui-input-invalid`。

## 受限的模型与 Transcript 输出

Adapter 为 Mastra Tool 安装了 `toModelOutput`、Display Transform 与 Transcript Transform。
原始 Proposal Input、Input Delta、执行结果与校验错误都会被替换成受限摘要。Domain Data Tool
继续独立存在，Query Row 始终留在服务端 Resource Gateway。

Mastra 会在 Per-tool Display/Transcript Transform 执行前创建 Tool-call Observability Span，因此只靠
这些 Transform 无法保护 Trace Input/Output。凡是安装了这个 Tool 的 `agent.generate()` 或
`agent.stream()`，都必须传入 `tracingOptions: presentUi.tracingOptions`；Adapter 把 `hideInput`
和 `hideOutput` 固定为 `true`。如果还要合并其他 Trace 配置，必须先展开其他配置，确保这两个强制
标志不会被覆盖：

```ts
const result = await agent.generate(messages, {
  tracingOptions: {
    ...otherTracingOptions,
    ...presentUi.tracingOptions,
  },
});
```

Executor 仍是宿主集成点。它必须与 `compiled` 使用同一份冻结 Catalog Slice，通过 Canonical
Compiler/Host Path Commit，并且只发布已经提交的 `SurfaceEventEnvelope`。Mastra 不能扩大本轮的
Contract Slice、Resource Grant 或 Authority。

```text
Mastra 1.61 Agent or Workflow
-> validated present_ui proposal
-> shared compiler + Host commit
-> trusted SurfaceEventStream
-> SurfaceController
-> GenerativeSurface
-> RendererRegistry
```

这个 Package 没有 Browser Export，也没有 `ArtifactPart` 或 `ArtifactRenderer` 兼容层。
