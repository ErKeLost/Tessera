---
title: AI SDK
description: 使用一个动态 Adapter 和一个 Renderer，把 Open Generative 接入 AI SDK 7.0.77。
---

`@open-generative/ai-sdk` 面向 AI SDK 7.0.77 及后续 v7 Patch，不提供 AI SDK v6 兼容路径。

## 服务端

高层 Adapter 直接返回 AI SDK v7 使用的 `tools + prepareStep`。`resolve` 返回 Host Turn，
不是另一层 UI Adapter。Tool Schema、Prompt 生成、Incremental Input、Repair 与 Commit 全部由
Package 内部负责。

```ts
import {
  createUIMessageStream,
  createUIMessageStreamResponse,
  streamText,
} from "ai";
import { createOpenGenerativeHost } from "@open-generative/host";
import { createOpenGenerativeAISdkAdapter } from "@open-generative/ai-sdk/server";

const host = await createOpenGenerativeHost();

const stream = createUIMessageStream({
  async execute({ writer }) {
    const openGenerative = createOpenGenerativeAISdkAdapter({
      tools: domainTools,
      writer,
      resolve: async () => host.prepareTurn({
        authority,
        resources: currentResources(),
        presentationPolicy: "auto",
      }),
    });

    const result = streamText({ model, messages, ...openGenerative });
    writer.merge(result.toUIMessageStream());
  },
});

return createUIMessageStreamResponse({ stream });
```

Resource 尚未就绪时，只有 Domain Tool 处于 Active 状态。下一个 AI SDK Step 中，Adapter 自动
启用 `present_ui` 并注入 Contract 生成的 Instructions。Commit 后，它写入已验证的 Surface
Data Part 并移除该 Tool。

Adapter 会在本次 `streamText` 调用中缓存第一个可用 Host Turn，因此 `resolve` 可以直接调用
`host.prepareTurn()`，应用不需要维护额外生命周期状态。

非 UI 服务端任务可以省略 `writer`，再调用 `openGenerative.drainEvents()`。

## 客户端

```tsx
import { OpenGenerativeRenderer } from "@open-generative/ui";
import "@open-generative/ui/styles.css";

<OpenGenerativeRenderer event={part.data} />
```

混合处理 AI SDK Parts 时使用 `isOpenGenerativeSurfaceDataPart()` 分流。Canonical Render Path
仍然只有一条：

```text
AI SDK v7 -> verified Surface data part -> OpenGenerativeRenderer
```

底层 Tool Constructor 仍供自定义 Host 使用；普通用户不需要编译或维护组件 Prompt。
