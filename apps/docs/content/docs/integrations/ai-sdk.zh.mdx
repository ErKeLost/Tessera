Tessera Studio 使用 AI SDK v7 的 UI Message Stream Protocol 连接 Nitro Server 与 React Client。

## 使用官方 Stream 装配

Mastra Stream 先通过 `@mastra/ai-sdk` 转换，再交给 AI SDK 官方的
`createUIMessageStream`。Text、Reasoning、Tool、Data Part、`reset-step`，以及不同 Step
重复使用 Part ID 的装配全部由 AI SDK 负责。

```ts
const stream = createUIMessageStream<TesseraUIMessage>({
  execute: ({ writer }) => writer.merge(agentStream),
  onStepEnd: async ({ responseMessage }) => {
    await checkpointUiMessage(responseMessage);
  },
  onEnd: async ({ responseMessage, isAborted, finishReason }) => {
    if (!isAborted && finishReason === "stop") {
      await checkpointUiMessage(responseMessage);
    }
  },
});

return createUIMessageStreamResponse({ stream });
```

AI SDK 对 `onStepEnd` 的正式定义就是在 Multi-step Agent Run 中持久化中间 UI Message。
因此 Tessera 不维护第二套 Chunk Assembler，也不创建兼容协议。

## Tessera Data Part

普通 Text、Reasoning 与 Tool 都保持 AI SDK 原生 Part。生成式分析视图通过 Tessera Message
Type 中唯一的 `data-openGenerativeSurface` Typed Data Part 传输，由 Studio 内置 Renderer 识别。

服务端只保存经过 Allowlist 的 Projection。同一个分析 Surface 的累积更新会覆盖旧 Snapshot，
每个 Step Checkpoint 也只 Upsert 同一个 Assistant Message ID。刷新 Thread 后恢复的是一条消息
和一个最新 Surface，而不是重复回放多份 Snapshot。
