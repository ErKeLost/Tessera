---
title: Mastra runtime
description: How Tessera Agent uses Mastra's native Agent, Processor, tool, workflow, and Memory APIs.
---

Tessera Studio currently runs its data agent on Mastra. Mastra is an internal
runtime dependency of the product, not a separate Tessera adapter that users
must wire into their application.

## Agent loop

Tessera constructs one Mastra `Agent` with the database tools, request-context
processors, presentation processor, and local `Memory` instance. The same Agent
owns every model step in a turn, including tool continuation and a resumed
database mutation after approval.

```ts
const agent = new Agent({
  id: "tessera-data-copilot",
  model,
  memory,
  tools: databaseTools,
  inputProcessors,
  outputProcessors,
});

const output = await agent.stream(message, {
  memory: {
    thread: threadId,
    resource: resourceId,
    options: {
      semanticRecall: false,
      workingMemory: tesseraWorkingMemoryOptions,
      observationalMemory: false,
    },
  },
  savePerStep: true,
});
```

`savePerStep` is Mastra's native persistence option. After every completed
generation step, Mastra flushes the current unsaved `MessageList` into the
configured Memory store. Tessera does not rebuild a user/assistant pair after
the stream finishes, so tool calls, tool results, and later assistant output are
not duplicated.

Observational Memory remains disabled because Mastra disables `savePerStep`
when observational memory is active. Semantic recall is disabled. Working
Memory is enabled with a Zod schema, `scope: "resource"`, `agentManaged: true`,
and `useStateSignals: false`, so stable domain context is deep-merged across
threads that share the same resource identity.

Mastra's internal `updateWorkingMemory` tool remains available to the Agent but
is filtered from Tessera's public AI SDK stream and browser transcript. It is
not a fifth business tool and cannot carry authorization or query evidence.

## Two persistence records

Mastra Memory is private model context. The browser receives a separate,
allowlisted UI transcript containing only safe text, reasoning summaries, tool
lifecycle summaries, and validated Tessera analysis views. AI SDK assembles
that UI message and Tessera checkpoints it after each completed step.

This separation prevents raw SQL, credentials, provider metadata, and query
rows from becoming browser history while still allowing a refresh to restore
the completed work.

## Suspended mutations

Database writes use Mastra's durable workflow suspension and `resumeStream()`.
The persisted workflow snapshot remains the authority for approval and resume;
the UI transcript is only a display projection and cannot authorize an effect.
