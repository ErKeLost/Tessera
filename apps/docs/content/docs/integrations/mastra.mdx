---
title: Mastra
description: Add Open Generative to a current Mastra 1.61 agent with one Processor and one Renderer.
---

`@open-generative/mastra` targets the current Mastra 1.61 Processor API only.
Applications do not compile component schemas, maintain UI prompts, register one
tool per component, or manage proposal transactions.

## Server

Create one Host and add one Processor to the existing Agent. `resolve` returns
`undefined` until a domain tool has produced renderable resources; the Processor
then builds and injects the single turn-scoped `present_ui` tool automatically.

```ts
import { Agent } from "@mastra/core/agent";
import { createOpenGenerativeHost } from "@open-generative/host";
import {
  MASTRA_PRESENT_UI_TRACING_OPTIONS,
  createOpenGenerativeMastraProcessor,
} from "@open-generative/mastra";

const host = await createOpenGenerativeHost();
const openGenerative = createOpenGenerativeMastraProcessor({
  resolve: async () => host.prepareTurn({
    authority,
    resources: currentResources(),
    presentationPolicy: "auto",
  }),
});

const agent = new Agent({
  id: "data-agent",
  name: "Data Agent",
  model,
  tools: domainTools,
  inputProcessors: [openGenerative],
});

const stream = await agent.stream(messages, {
  tracingOptions: MASTRA_PRESENT_UI_TRACING_OPTIONS,
});
```

When the Agent streams, the Processor writes the committed
`data-openGenerativeSurface` part through Mastra's own Processor writer. It
removes `present_ui` after commit. The application does not drain or translate
Surface events.

The Processor caches the first available Host Turn in Mastra's request-scoped
processor state. `resolve` may call `host.prepareTurn()` directly; applications
do not keep a per-step Turn cache.

The tracing options are required whenever Mastra tracing is active because
Mastra creates tool-call spans before display and transcript transforms run.
They prevent proposal payloads from entering trace input or output.

## Client

Render the data part with the package-owned Renderer:

```tsx
import { OpenGenerativeRenderer } from "@open-generative/ui";
import "@open-generative/ui/styles.css";

<OpenGenerativeRenderer event={part.data} />
```

The Renderer owns the verified Contract Registry, `SurfaceController`, official
Renderer Registry, replay, cleanup, loading state, and command bridge. A Host
only supplies `onCommand` when the surface exposes interactions.

```text
domain tool -> Resource -> Mastra Processor -> present_ui -> committed data part
-> OpenGenerativeRenderer
```

Low-level tool/session constructors remain available for custom Hosts, but they
are not part of the normal application integration.
