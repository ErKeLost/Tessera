---
title: Tool 契约
description: Tessera Agent 实际暴露给模型的数据库 Tool，以及每个 Tool 强制执行的边界。
---

Tessera Agent 通过一组少量、明确的 Mastra Tool 执行数据库工作。生成式分析视图**不是**额外
Tool；它在可信数据已经产生后，由 Agent 的 Output Processor 生成。

## 面向模型的 Tool

| Tool | 用途 | 关键边界 |
| --- | --- | --- |
| `list_database` | 列出 Relation、描述精确 Schema 或 Relation、检查 Studio 当前 Relation、读取引擎能力 | Metadata 只能帮助规划，不能证明用户询问的业务事实 |
| `search_data_context` | 搜索或描述受治理的 Semantic Catalog | 返回受限 Semantic ID，不执行查询 |
| `prepare_analysis` | 校验、绑定并编译 Semantic Draft，签发短时 `analysisRef` | 不读取业务 Row，也不返回编译后的 SQL |
| `execute_sql` | 执行显式只读 SQL、消费 `analysisRef`，或提交类型化 Mutation | 唯一的业务数据执行边界 |

Extension 与 RLS 检查属于 `list_database` 的 `operation=extensions` 和
`operation=rls_policies`，不是独立的模型 Tool。

一次请求只选择一条主要查询路径：

```text
物理结构或显式 SQL 工作
  list_database -> execute_sql

语义业务分析
  search_data_context -> prepare_analysis -> execute_sql(analysisRef)
```

Catalog 与 Schema Result 只用于规划，只有成功的执行结果才能支持数据结论。`not_found`、
`unavailable`、`blocked` 与 `failed` 是不同状态；不完整 Catalog 绝不能被改写成“Relation 不存在”。

## Tool Result 契约

每个公开 Tool Result 都有明确上限，并且包含可行动信息：Status、安全的 Count 或 Metadata、
可选 Reason，以及能够恢复时的 Next Action。浏览器 Tool Part 只保存 Allowlist 摘要，不保存
原始参数、SQL、Credential、Catalog 内部信息或 Query Row。

`execute_sql` 的 Mutation 分支不会把模型意图当成授权。服务端负责编译 Typed Action、评估当前
Policy、创建 Approval Checkpoint，并且只在收到有效决定后恢复同一个 Mastra Run。Raw Write SQL
不被接受。

## 生成式分析视图

`execute_sql` 发布可信 Resource 后，Output Processor 可以把最终回答转换成
Tessera 分析视图。这个 Processor 只能看到当前 Resource Descriptor 与组件词汇；它不会增加
呈现 Tool、不会为每个图表增加一个 Tool，也不会创建第二条查询路径，更不能执行数据库工作。

浏览器最终收到一个 Typed AI SDK Data Part。Tessera 负责校验、脱敏、逐 Step Checkpoint，
并通过 Studio 内置 Renderer 输出。

## Trust Boundary

| 层 | 负责 | 不能做 |
| --- | --- | --- |
| Model | 选择有效 Tool，并提出受限 Input | 授权自己、读取 Credential 或绕过 Policy |
| Mastra Agent | Step Loop、Processor、Tool 生命周期、Memory、Suspend/Resume | 取代 Tessera 的数据库授权 |
| Tessera Server | Catalog Scope、SQL Safety、Connector 执行、Approval、Evidence、Transcript Projection | 把原始模型输出直接当作可信状态 |
| Browser | 渲染原生 AI SDK Part，并提交明确的用户决定 | 连接数据库或执行 Effect |
