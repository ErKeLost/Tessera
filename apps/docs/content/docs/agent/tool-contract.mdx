title: Tool Contract and Boundaries
description: Keep model tools semantic, browser output redacted, and database execution server-owned.
---

## Model-facing tools

```text
inspect_current_context  -> server-bound current data context
inspect_catalog          -> semantic catalog slice for one question
describe_data            -> bounded detail for inspected entities
probe_data               -> fixed, bounded discovery probe
run_analysis             -> read-only analysis from a semantic draft
```

Tools accept semantic identifiers returned by the current catalog. They do not
accept SQL, connection strings, credentials, physical relation names, compiler
output IDs, or arbitrary query limits. A final answer must be grounded in a
verified `run_analysis` result.

## Trust boundaries

| Boundary | Allowed | Never allowed |
| --- | --- | --- |
| Model | Semantic slices, opaque IDs, bounded evidence | SQL, credentials, physical table names |
| Browser | Redacted lifecycle, safe narration, validated artifacts | Raw tool arguments, private traces, connector access |
| Studio server | Authentication hooks, orchestration, filtering, persistence | Bypassing host authorization |
| Data Agent | Live catalog, signed scope, typed draft, bounded result | Caller-supplied SQL or out-of-scope analysis |
| Write surface | Typed mutation, purpose, idempotency, approval | Implicit writes from read analysis or free-form SQL |
