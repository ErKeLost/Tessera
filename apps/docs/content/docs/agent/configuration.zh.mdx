---
title: 配置
description: 配置 Tessera Studio、数据库安全边界与模型运行时。
---

Tessera 读取一份只在服务端使用的 `tessera.config.ts`。它负责数据库连接、语义定义、模型设置与
Studio 网络边界。生成式分析视图已经内置在 Studio 中，没有独立安装步骤或公开配置块。

```ts
import { defineTesseraConfig } from "@open-tessera/studio";

export default defineTesseraConfig({
  database: {
    url: process.env.DATABASE_URL!,
    schemas: ["analytics"],
    maxRows: 5_000,
    statementTimeoutMs: 30_000,
  },
  llm: {
    model: "openrouter/qwen/qwen3.8-27b",
    reasoningEffort: "low",
    temperature: 0.1,
    maxOutputTokens: 12_800,
    maxSteps: 50,
    maxRetries: 0,
  },
  studio: {
    host: "127.0.0.1",
    port: 4317,
    catalogCacheTtlMs: 60_000,
  },
});
```

## 数据库

`database.url` 为必填项。除非同时提供匹配的 `database.dialect`，Tessera 会从 URL 推断方言。
PostgreSQL 与 MySQL 可以通过 `schemas` 收窄发现范围；`maxRows`、`statementTimeoutMs` 与
`permissions` 共同限制 Agent 可以执行的工作。

Turso 凭据使用 `database.authToken` 或 `TURSO_AUTH_TOKEN`，Token 必须与数据库 URL 分开。

## 模型

模型 ID 使用 Mastra 的 `provider/model` 格式。Tessera 可以从常见供应商的服务端环境变量读取
API Key，也可以在只对服务端可见的配置中提供 `llm.apiKey`。`llm.baseUrl` 与 `llm.headers`
用于兼容网关。

`maxSteps` 限制完整的模型与 Tool 循环，`maxRetries` 控制供应商重试。呈现校验有独立且受限的
Processor Retry，不会给 Agent 增加额外 Tool。

## Studio 网络边界

Studio 默认只监听 Loopback。使用非 Loopback Host 时必须同时满足：

- `studio.allowRemote: true`
- 保持 Authentication 开启
- 至少配置一个明确的 `studio.allowedOrigins`

这样可以避免本地数据库工作区被意外暴露到远程网络。
