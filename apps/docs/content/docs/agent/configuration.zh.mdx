description: 在不虚构公开 Studio 配置 API 的前提下，让 Tessera Agent Generative UI 证明可复现。
---

这套 Generative UI 成功证明不依赖另行发布的 `@open-tessera/studio` 配置 Facade，
当前也不存在 `tessera-agent` 组件 CLI。它的配置由明确的 Package Contract 与测试 Fixture
负责，而不是再创建一套顶层产品 API。

## 所有权

| 关注点 | 当前 source of truth |
| --- | --- |
| Protocol Limit 与 Wire Schema | `packages/protocol` |
| Component Identity、Schema 与 Catalog Slice | `packages/catalog` 与 `packages/components` |
| Proposal Normalize、Validate 与 Commit | `packages/compiler` |
| Query Resource、Grant 与 Projection | `packages/resources` |
| Host Authority、Session 与可信事件 | `packages/server` |
| 浏览器 Replay、Resolved Props 与 Command | `packages/client` |
| React Surface 与精确 Renderer Lookup | `packages/react` |
| Tessera data-agent Renderer 与 Recipe | `packages/ui` |
| 确定性测试与模型评测验收 | 成功证明规范与 Fixture |

Host 必须为每个 Surface Session 冻结 Component Contract Slice、Authority、
Resource Grant、Limit、Locale、Timezone 与 Renderer Capability Manifest。
模型无权配置或扩大其中任何一项。

## Data Agent Profile

当前产品 Profile 固定为一个 `data.chart` Component Contract 与 17 个经过审计的 Recipe。
这些 Recipe 在同一 Contract 上组成严格 Discriminated Union；它们不是额外协议组件类型，
也不能注入任意展示属性。

Query Row 始终留在 Resource Gateway。模型只能看到受限、经过 Policy 批准的 Descriptor 与
Binding Reference。可信事件到达 `SurfaceController` 后，Renderer Props 才会按单个 Node 解析。

## 本地环境

确定性证明门槛不需要任何 Secret。`OPENROUTER_API_KEY` 只会启用可选的文档聊天 Route。
数据库凭据与 Tessera Agent 产品集成属于其 Host 产品界面，并且在那里也必须只保留在服务端。

未来如需公开配置 Facade，必须先完成实现和测试，再写入本文档。在此之前，示例只使用仓库中
真实存在的 API 与 Fixture。
