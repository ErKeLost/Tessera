---
title: Configuration
description: Keep database and model credentials server-only while configuring Studio limits and policy.
---

Create `tessera.config.ts` in the project directory and resolve secrets from the
server environment:

```bash
DATABASE_URL=postgresql://readonly:password@127.0.0.1:5432/warehouse
OPENROUTER_API_KEY=your-server-only-key
```

```ts
import { defineTesseraConfig } from "@tesserae/studio";

const databaseUrl = process.env.DATABASE_URL;
if (!databaseUrl) throw new Error("DATABASE_URL is required.");

export default defineTesseraConfig({
  database: {
    url: databaseUrl,
    maxRows: 500,
    statementTimeoutMs: 15_000,
  },
  llm: {
    model: "openrouter/qwen/qwen3.8-27b",
  },
});
```

Tessera infers the database dialect from the URL. Pin `database.dialect` only
when the config must reject a URL from another database family.

## Model settings

Use a Mastra-supported `provider/model` ID and its provider environment key.
An OpenAI-compatible gateway can provide a server-only `baseUrl`, `apiKey`, and
headers. Never expose these values through browser environment variables.

## Workspace settings

| Section | Responsibility |
| --- | --- |
| Database | URL, dialect, schema scope, and connection test |
| Model | Provider, model, API key, base URL, and reasoning effort |
| Limits | Maximum rows, statement timeout, and Agent step limits |
| Permissions | Read, write, destructive, and unknown action policy |

Sensitive settings changes are applied by the server runtime and can be gated
by the host authentication and administrator policy.

## Listener options

```bash
npx data-elements@latest studio \
  --config ./config/tessera.config.ts \
  --host 127.0.0.1 \
  --port 4310
```

Non-loopback listeners require explicit remote access, allowed origins, and
authentication in the Studio config.
