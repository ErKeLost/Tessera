---
title: 运行流程
description: 理解一个问题如何变成经过验证的答案和可审查证据。
---

面向用户的路径是固定的：

```text
问题 -> Catalog -> 语义计划 -> 受限只读查询
    -> 验证 -> 证据 -> Markdown 答案
```

| 步骤 | 用户看到的结果 | 服务端职责 |
| --- | --- | --- |
| 连接 | Studio 显示已配置数据库 | 把 Connector 和凭据留在服务端 |
| 发现 | 出现相关实体、字段、指标和关系 | 加载实时 Catalog 并返回受限语义切片 |
| 澄清 | 歧义变成明确选项 | 描述已检查实体或执行一次受限 Probe |
| 计划 | 出现可审查的只读分析意图 | 只接收语义 ID，不接收模型生成的 SQL |
| 执行 | 结果和进度流入 Thread | 重新验证 Scope、编译、执行并应用限制 |
| 发布 | Markdown 答案和证据 | 脱敏私有细节并发布受限证据 |

## 公开生命周期

浏览器接收产品阶段，而不是私有 Tool Payload：

`catalog`、`retrieval`、`planning`、`probing`、`compiling`、`executing`、
`verifying`、`publishing` 和 `narrating`。

只有阶段状态、受限耗时、安全叙述和证据引用会穿过 Browser 边界。SQL、Connector
元数据、物理 Catalog 名称、原始 Tool 参数和不受限查询输出都留在服务端。

## 重试与中断

每次分析都会在执行前重新绑定当前 Catalog。过期 Capability 或变化后的 Catalog
会 Fail Closed，而不是继续执行旧计划。用户可以中断、重试、澄清或在同一 Thread
继续追问，浏览器始终不会获得数据库直连权限。
