---
title: 运行流程
description: 一个 Tessera 问题如何变成有依据的回答。
---

一次 Tessera Turn 从问题到最终 UI 只有一条受治理链路：

```text
问题
-> 检查物理 Schema 或语义 Catalog
-> 执行一条受限数据库路径
-> 校验并保留证据
-> 组织最终回答
-> 传输一条对浏览器安全的 AI SDK Message
```

## 1. 选择一条查询路径

Tessera 不会把所有数据库 Tool 都运行一遍，而是选择一条主要路径：

| 请求 | Tool 路径 |
| --- | --- |
| 明确 SQL、物理表或列、行数据检查 | `list_database -> execute_sql` |
| 业务指标、排行、趋势、分组分析 | `search_data_context -> prepare_analysis -> execute_sql(analysisRef)` |
| 引擎、Extension 或行安全元数据 | 只调用对应的 `list_database` Operation |

Catalog 与 Schema 结果只是规划上下文。只有成功执行的 Query 或 Analysis Result 才能支撑数据论断。

## 2. 在权限边界内执行

服务端先把每次执行分类为 `read`、`write`、`destructive` 或 `unknown`，再重新校验权限、方言、范围、
行数上限、超时与取消信号。无法可靠分类的操作直接拒绝；读取仅在允许时执行。Mutation 使用类型化
Input 与持久审批 Checkpoint，聊天消息不能自行授予权限。

## 3. 保存每个已完成 Step

Mastra Memory 使用原生 `savePerStep`，因此已完成的 Tool Call 与 Result 会提供给后续模型 Step，
Turn 中断后也不会丢失。Studio 通过 AI SDK `onStepEnd` 保存另一份经过脱敏的 UI Transcript。
两份记录服务于不同 Trust Boundary，不再由 Tessera 手工重建。

## 4. 生成回答

Tessera 根据已验证的 Evidence 返回有依据的 Markdown。浏览器接收 AI SDK 原生 Text、Reasoning
和 Tool Part；刷新 Thread 后恢复同一份脱敏后的消息。
