---
title: Run Workflow
description: How one Tessera question becomes a grounded answer and an optional analysis view.
---

One Tessera turn has a single governed path from the question to the final UI:

```text
question
-> inspect the physical schema or semantic catalog
-> execute one bounded database path
-> validate and retain evidence
-> compose the final answer
-> optionally compile a generated analysis view
-> stream one browser-safe AI SDK message
```

## 1. Choose one query path

Tessera does not run every database tool. It selects one primary path:

| Request | Tool path |
| --- | --- |
| Explicit SQL, physical tables or columns, row inspection | `list_database -> execute_sql` |
| Business metric, ranking, trend, grouped analysis | `search_data_context -> prepare_analysis -> execute_sql(analysisRef)` |
| Engine, extension, or row-security metadata | The matching `list_database` operation only |

Catalog and schema results are planning context. Only a successful query or
analysis result is evidence for a data claim.

## 2. Execute within authority

The server classifies every execution as `read`, `write`, `destructive`, or
`unknown`, then revalidates permissions, dialect, scope, row limits, timeout,
and cancellation. Unknown operations are denied. Read operations run directly
only when allowed. Mutations use typed inputs and a durable approval checkpoint;
a chat message cannot grant its own permission.

## 3. Preserve completed steps

Mastra Memory uses native `savePerStep`, so completed tool calls and results are
available to later model steps and survive an interrupted turn. Studio stores a
separate, sanitized UI transcript through AI SDK `onStepEnd` checkpoints. The
two records serve different trust boundaries and are not manually reconstructed.

## 4. Produce the response

After a database tool publishes a verified dataset, Tessera's internal output
processor can select from the available analysis recipes and compile a
declarative view. This is response formatting, not another Agent tool and not a
second query. If no suitable dataset exists, Tessera returns the normal text and
tool transcript without fabricating a view.

The browser receives native AI SDK text, reasoning, and tool parts plus at most
the latest committed analysis-view snapshot for that response. Refreshing the
thread restores the same message instead of replaying every intermediate copy.
