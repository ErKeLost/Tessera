---
title: Generated analysis views
description: How Tessera Agent turns verified query resources into a safe, structured answer view.
---

Tessera Agent can return a structured analysis view next to its text answer.
The feature is built into Tessera Studio and follows the same database,
permission, memory, and transport boundaries as the rest of the response.

## One answer path

```text
question
-> database tool step
-> verified Resource + Evidence
-> final presentation language
-> server validation and commit
-> typed AI SDK data part
-> Studio renderer
```

The model does not call a UI tool. Once a database tool has produced a verified
resource, Tessera's Mastra output processor supplies the bounded presentation
vocabulary for the final model step. Complete statements are compiled while
streaming; source presentation text is not displayed in chat.

The processor publishes a view only after the complete declaration passes
schema, resource-binding, authority, and commit checks. Invalid output can
trigger one bounded Processor retry. That retry disables domain tools, so a
presentation correction cannot execute the database query again or create a
tool loop.

## Data stays with Tessera

Query rows are not copied into the model-authored declaration. The model binds
a chart or metric to an opaque resource and to offered column names. Tessera
resolves and validates the node-scoped dataset immediately before rendering.

The browser never receives database credentials, connector handles, authority
objects, compiler state, or raw model proposals. It receives native AI SDK
parts plus the committed, typed analysis-view data part.

## Current view vocabulary

Tessera currently uses six analytical concepts:

- report
- stack
- grid
- metric
- insight
- data chart

The data chart supports 17 audited recipes. A recipe selects an information
structure and valid column bindings; it cannot contain arbitrary CSS, colors,
callbacks, React props, JavaScript, SVG markup, URLs, SQL, or tool names.

The renderer is built from local shadcn/ui-style primitives and Recharts where
appropriate. Theme values are controlled by Tessera's CSS tokens, not by model
output.

## Failure and refresh behavior

The last committed view remains available if parsing, validation, policy,
timeout, abort, or conflict handling fails. During a multi-step answer, AI SDK
assembles the UI message and Tessera checkpoints the same assistant message at
every `onStepEnd`. Cumulative updates replace the earlier surface snapshot, so
a refresh restores one latest view instead of several stacked copies.
